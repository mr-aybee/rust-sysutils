# disklens benchmark report

> These results come from a single host. They are not guarantees.

## Environment

| Item | Value |
|---|---|
| CPU | Intel Xeon E5-2620 v2 @ 2.10 GHz, 16 logical CPUs |
| Memory | 62 GiB |
| OS / filesystem | Linux 6.8.0-147-generic x86_64, ext4 on local disk |
| Rust | rustc 1.100.0 (0ef1bc386 2026-11-09) |
| Build profile | `release`: `lto = "thin"`, `codegen-units = 1`, `opt-level = 3`, `strip = true` |
| Reference | GNU coreutils `du` 9.4 |
| Date | 2026-11-25 |

## Workloads

- **Fixture**: 100,000 files (0–4 KiB, fixed random seed) in 1,101 directories, generated by `scripts/bench-disklens.sh`.
- **Real tree**: `/usr` on the reference host, 131,311 files, scanned with `-x`.

Runs used `hyperfine -N` (10 runs warm, 5 runs cold). Cold runs executed `sysctl vm.drop_caches=3` before each run.

## Correctness

| | On disk (bytes) | Apparent (bytes) |
|---|---|---|
| `du -s -B1` / `du -s -b` | 413,995,008 | 204,865,281 |
| disklens | 413,995,008 | 204,865,281 |

Totals were also identical to `du` on `~/.cargo`, `/usr/share` and `/usr/lib` on this host.

## Results against the engineering targets

| Target (from project plan) | Measured | Status |
|---|---|---|
| Scan 100,000 files in < 5 s on a warm local SSD | 57.1 ms ± 3.2 | Met |
| Report cold-cache results separately | 396 ms ± 77 (du: 2.99 s) | Reported |
| < 100 MiB RSS | 3.8 MiB (fixture), 12.8 MiB (`/usr`) | Met |

## Timings

| Workload | `du -s` | disklens `-j 1` | disklens `-j 4` | disklens (16 threads) |
|---|---|---|---|---|
| Fixture, warm | 504.9 ms ± 152.4 | 514.3 ms ± 120.0 | 161.3 ms ± 77.3 | **57.1 ms ± 3.2** |
| Fixture, cold | 2.988 s ± 0.259 | — | — | **396.2 ms ± 76.9** |
| `/usr` (`-x`), warm | 1.018 s ± 0.173 | — | — | **136.8 ms ± 10.5** |

With one thread, disklens matches `du`, so the speed-up comes from parallel directory reads rather than from doing less work. From a cold cache, parallelism keeps several metadata reads in flight, which the device handles concurrently.

## Reproducing

```sh
scripts/bench-disklens.sh [workdir]    # cold runs need passwordless sudo
```

## Known limitations

- One host with a local SSD. Network filesystems and spinning disks behave differently, and high parallelism can hurt on HDDs. Use `-j` to tune.
- Windows and macOS have not been benchmarked.
